# 纪律（disciplines）

> 本文件是**判据集合**，不是说明文档。每条给出：判据（怎么判断违反了）＋ 落点（在哪被强制）。
> 落点为「规约」= 只写在文本里，**接受它会被跳过**（见 D-02）；落点为路径 = 有机制。
> 只增不改：旧条目正文不动，修订另起一条并标注取代关系。**条目按编号严格递增排列**（D-47），
> 因为乱序会掩盖删除——这条本身就是被一次未被发现的原地替换逼出来的。机制：`npm run check:disciplines`。
>
> 与老仓库的关系：`work-flow`（留档）的 `docs/run/hard-won-constraints.md` 30 条尚未迁移，
> 迁移后落在 `docs/constitution.md`，编号 A1–F3 保持不变。本文件只放**架构层纪律**——
> 决定形状的那几条，以及本轮讨论新增的。两者不重复：宪法管「实现别重踩坑」，本文件管「东西长成什么样」。

## 一、形状（violating these = 换了一个东西）

| id | 纪律 | 判据 | 落点 |
|---|---|---|---|
| D-01 | **生产者不能宣布自己完成** | 判定「完成」的一方，其产出不被自己评判 | dev / tester 上下文隔离（架构） |
| D-02 | **纪律不进拦截链就不会被遵守** | 任何「必须写 X」的要求，要么在 `tool_call` 里 `block`，要么显式承认会被跳过 | 各 gate；本表「落点」列 |
| D-03 | **可推导的值不让人填** | 存在两处必须字符级一致、由人手写的值 = 违反 | 配置单点（03-config） |
| D-04 | **一概念一权威文件** | 同一规则写全在两处 = 违反；其余只链不复述 | 评审时人查 |
| D-05 | **散文里不留第四类** | 为什么 → `decisions.md` 一行；是什么 → 接口文件；必须恒成立 → 测试。三者之外不写散文 | 评审时人查 |
| D-06 | **架构文档是脚手架，不是建筑** | `docs/modules/*.md` 在对应代码落地后必须收缩：职责 + 不负责什么 → 模块目录的文件头注释；设计点 → 测试名；取舍理由 → `decisions.md` 一行。只留 `modules/README.md` 的依赖图。**代码已落地而文档未收缩 = 两份权威（D-04）** | 验收时人查；模块完工即检 |
| D-07 | **pi 只能作为参数进来** | `src/` 里出现 pi 的值导入（非 `import type`）= 违反；handler 拿到的 `ctx` 存进模块作用域 = 违反。理由不是洁癖：模块级可变状态一出现，三个角色同进程加载就共享同一份，e2e 整条路不成立（「某一层没法在同进程里驱动」的真实形态是这个，不是缺 API） | 07-adapter 验收 A9 |

## 二、决策与规划

| id | 纪律 | 判据 | 落点 |
|---|---|---|---|
| D-10 | **能不能精确陈述，不是能不能回答** | 问题已能精确陈述 → 进未决表（哪怕答不了）；陈述不清 → 留散文，**不许预先切成条目** | 澄清规约 |
| D-11 | **想直接动手了 = 该交棒了** | 澄清/规划会话里开始写生产代码，即为越界信号 | 澄清规约 |
| D-12 | **决策记录只在实现之后写** | `decisions.md` 不得记录尚未落地的决定 | 澄清规约 + 评审 |
| D-13 | **写记录的双条件** | 同时满足：有人真主张过一个具体替代方案 ＋ 否决理由读代码看不出来。不满足则降级为测试名 / 注释 / 不写 | 评审时人查 |
| D-14 | **已 PASS 的里程碑节冻结** | 回头修改已验收里程碑的断言或结论 = 伪造记录 | 规约（拟机制化，见未决） |
| D-15 | **断言节只有人能改** | arch 可改状态标记、未决表、风险节；不得改断言。arch 认为断言错了 → 往「风险与未决」写清该怎么改 + `escalation` 升级给人，由人改（多一次往返，换「断言源不被产出链修改」） | 规约（拟机制化，见未决） |
| D-16 | **规划书要能塌缩** | 最小合法形态 = 一个里程碑 + 一条断言 + 未决表「无」。模板撑不住这个塌缩即为超重 | 04-plan 解析器 |
| D-17 | **归档不进每轮读序** | 任何规约里出现「每轮读 `decisions.md`」= 违反（归档变成了每轮成本） | 06-roles 评审 |
| D-18 | **规约可追加不可替换** | 项目侧只能追加一段说明（`roleNotes`），不得覆盖角色规约本体——否则 tester 可被换成橡皮图章（D-01 的形状） | 03-config 字段表 |

## 三、断言与验证

| id | 纪律 | 判据 | 落点 |
|---|---|---|---|
| D-20 | **`[auto]` / `[human]` 二分** | 每条断言必须标其一；`[auto]` 须含命令或路径，`[human]` 不得为空 | 04-plan 解析器 + gate |
| D-21 | **`[human]` 是人的原话** | 人工关卡只问 `[human]` 条目；它应在澄清阶段由人说出，不由 AI 归纳 | 澄清规约（无法检查，接受稀释） |
| D-22 | **仪式量从断言表推导** | 产出文件要求 = 每条断言一行结论。固定小节数 = 违反（小改动会被迫凑格式） | 05-gates |
| D-23 | **无自动化基建时显式降级** | 项目无法自动测 → 必须显式声明该 gate 为空，不得静默降级 | 03-config 诊断 |
| D-24 | **逐条签字** | 规划书写盘前，断言逐条过人；整份「你看一下」不算签字 | 澄清规约 |
| D-25 | **测试输入走真实解析路径** | 被测对象消费的结构（`Milestone` / `Config` / `Message`）不得在测试里手写字面量，必须由真实解析器从真实文件产出。字面量 = 测试与解析器脱钩：语法变了字面量仍能跑，测试继续绿而真实链路已断 | 04-plan / 05-gates 验收节；各模块测试评审 |

## 四、外部化与不自造

| id | 纪律 | 判据 | 落点 |
|---|---|---|---|
| D-30 | **载体必须在视线路径上** | 需要人主动去打开才能看见的待办 = 无效载体。未决/待回状态必须出现在 `/status` 与启动简报里 | 01-channel + 07-adapter |
| D-31 | **成熟方案优先** | 需要工具/机制时先查现成方案（pi 原生能力、issue tracker、npm 包），有可用的直接用 | 评审时人查 |
| D-32 | **环境即边界** | 编译/工具链/环境错误不循环尝试：记录 + 报告，最多试 1 次替代 | 角色规约 |
| D-33 | **开窗口由人执行** | 不在 agent 会话内开窗口 / 浏览器 / IDE。无例外 | 角色规约 |
| D-34 | **物理删除归人** | AI 可提议删除并给出依据，不执行 | 角色规约 |

## 五、机制增殖（本项目的死因）

| id | 纪律 | 判据 | 落点 |
|---|---|---|---|
| D-40 | **新机制的双问** | ①有没有被观察到的失败模式？②它保护用户能力，还是保护本仓库的自证？后者需额外理由 | 评审时人查 |
| D-41 | **自检不得超过运行时** | 测试代码行数 > 运行时代码行数 = 红线，需停下来审。口径写在脚本文件头（分母 = `tests/**/*.ts` 全量减排除，不是仅 `*.test.ts`——否则「把测试逻辑挑出 .test.ts 就能躲红线」）。阈值 1.0 不上调；红了做**构成 diff**（新增测试在测真实行为还是仪式），审的结论写进脚本文件头，**不改数字** | `npm run check:testsize`；红时人审 |
| D-42 | **升级由不够用触发** | 未决表 → 依赖拓扑 → 独立票系统，每级由一次真实的「装不下了」推上去，不由预判 | 评审时人查 |
| D-43 | **超预算先砍功能** | 接入成本超预算时，优先砍功能或加默认值，其次才改文档 | 08-分发 |
| D-44 | **措辞类人工检查分散到各里程碑** | 规约措辞、拦截提示文案、语法手感这类无法机械检测的断言，必须挂在产出它的那个里程碑，不得汇总到最后。措辞一旦嵌进工具链，改一句牵十处；每站查轮胎比终点站发现胎瘪更少打断节奏——因为不用返工 | 写规划书时人查 |
| D-45 | **一个提交一件事** | 同一提交里装两件不相干的改动 = 违反。判据：如果其中一件需要回退，能不能 `git revert` 一条就完？不能则当时就该拆 | 提交时人查 |
| D-46 | **D-45 覆盖固定提交数** | 「每里程碑三个 commit」本质上是**顺利路径断言**，不是提交纪律。两者冲突时 D-45 优先。判据：固定数一旦被当成硬指标，返工时它只能逼你做两件坏事之一——squash 掩掉返工（丢中间状态，而中间状态正是「断言没迁就实现」的唯一证据），或把多个不相干改动塞进一个 commit（直接违反 D-45）。所以固定数只能是下限，不能是上限 | plan.md 提交纪律节；提交时人查 |
| D-47 | **只增不改有机制** | 本文件的条目只增不减。判据：某条 D-xx 在某次改动里消失（`-` 侧有、`+` 侧无）= 违反（修订走新编号 + 标注取代关系，不是原地替换）。条目按编号严格递增排列——乱序会掩盖删除，递增则少一个号一眼看得出。兼查本表声称的 `npm run x` 真存在且已接线（D-02）。来源：`42bd0e7` 把 D-44 整行替换成 D-45，违反的是本文件自己表头第三条，两个提交无人发现 | `npm run check:disciplines`（已串 pretest） |
| D-48 | **获得常驻机制的条目离开每轮读序** | 某条纪律拥有**常驻机制**（每轮 `npm test` / 每次提交都跑的 gate）的那一天，它离开 AGENTS.md 的读序；被 block 时以机制输出为准。**一条一条生效，不按「落点列有路径」批量判**——D-07（落点 A9，M6 一次性验收）、D-25（验收节）、D-30（`/status` 尚未落地）的路径不是每轮跑的，移出 = 在 M6 之前既不在脑子里也没 gate 在跑 = 等于删除。前提：机制的报错文本必须自带判据原文（移出后，agent 第一次知道该条存在就是被拦的那一刻） | AGENTS.md；新增机制时人查 |
| D-49 | **导出必须有生产调用点** | `src/` 与 `extensions/` 的每个导出值（函数 / 常量）零生产调用点 = 违反。只被 re-export、只被测试调用都不算。二选一：接线，或连测试一起删（D-34：执行归人）。来源：`watchInbox` 有实现、有 C1–C8 八条测试、`status.ts` 注释写着已接线，而 `git log -S` 证明从未接线——289 用例与 11 次审计全没抓到，抓到它的是一条人写的 `[human]`（M6.6 判 FAIL，人手动踢 47 分钟）。**这一档比 skill 更坏**：执行力排序里「有代码无调用点」排在「skill/规约」之后——规约你知道它会被跳过，机制你以为它在跑，而它伪装成有实现有测试有文档。M6-010 修的是那一个实例，本条修这个类（首次运行照出 5 个：`configGate` / `chainFor` / `commandGateStatus` / `takeSourceBaseline` / `validate`）。已知盲区：函数内部的死分支（如 `research` 的 `finish`）抓不到 | `npm run check:wiring`（已串 pretest） |
| D-50 | **目的变更必清点** | 某角色/机制的「存在理由」改变时（记进 decisions 的那次变更），旧职责必须逐项重审：仍需要 / 是惯性，结论落进角色规约或删除。判据：目的变更后，角色规约里仍存在「按新目的不成立的职责」= 违反。来源：arch 从「规划者」（demo 形状的惯性）变「人的代理」（D-01 推出）后，四件旧职责逐项清点——没有纯惯性，但前三件（分发/收尾/升级裁决）从「自主」变「代理触发」；retro 说「arch 该退场」的解法错了，正解是换目的不是删角色（二次系统效应的正面解法：承认存在、在目的变更的每个节点重新清点，Brooks） | 决策记录（每次角色/机制目的变更伴随一次清点）；评审时人查（规约级，接受会被跳过） |
| D-51 | **判据持有权在人（gate 判据变更要人批）** | gate 判据本体（匹配规则 / 阈值 / 必填字段 / check 脚本判据）的修改 = 体系结构变更，agent 必须先按 D-15 同款形状升级给人（写清怎么改+为什么+三选项）再等批；擅自改 = 违反。判据 vs 实现的分界线：判据本体要人批，reason 措辞 / 代码重构 / 新 gate 接线 agent 自主。来源：Goodhart——评分函数是判据的投影，投影漏维度；持有权交给产出者（agent），投影上没有的东西就消失（A9f 的 G_release 三段标签可被捏造，投影漏了「人真的被问过」，被并行 agent 抓到才补上 state.awaitingHuman）。与 D-15 的区别：D-15 管 plan.md 断言节，本条管 gates 代码里的判据——两者都是「评分函数不能改自己的判据」 | arch.md（规约级，接受会被跳过）；分界线清单在 human.md |
| D-52 | **配置字段必须有消费点** | `wf.config.json` 的每个字段（`FIELDS` 表的键）必须在 `src/` 里被真的读取（`cfg.<key>`）。有解析、有诊断、有模板示例，而没有人读它 = 违反。二选一：接线（并补一条从公共入口验「配了就生效」的测试），或从 FIELDS 删掉——承认它不存在，而不是留一个人填了不生效的字段。**这一档是 D-49 的盲区**：D-49 问「导出有没有调用点」，而这里函数都活着、死的是参数与字段（`roleNotes` 是漏传的第三参，`maxRounds` 被 State 默认值遮蔽）。比 D-49 更坏一点：配置是**人填的**，静默忽略会让他以为自己配了（老仓库 `testCmd` 不配就静默降级是同病，03-config 文件头记着）。已知盲区：解构写法与「读了没用对」抓不到，写在脚本文件头 | `npm run check:config`（已串 pretest） |
