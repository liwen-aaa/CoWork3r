# M6.6 真跑实测记录：FAIL（自动成环未成立）

> 方式：真 pi 三窗口（临时空项目，pi install -l 接入） ｜ 执行者：人 + 帮手独立核查
> 日期：2026-08-22 ｜ 判定：**FAIL**（[human] 断言二，人判）

## 判定

**M6.6 判 FAIL**。核心断言「在一个新建空项目里真开三个窗口，跑通一个里程碑——
这是唯一能证明它真的在运行的事」**未成立**：流程中没有任何一环是窗口自动处理的，
全部关键动作靠人向窗口注入指令。判据 1（每个窗口收到该收到的 type，无静默故障）
不成立。

## 现象（实测）

1. arch 分发、dev 产出、tester 验收各环节，窗口均**不自动处理收件箱消息**——
   每次都必须人在窗口手动输入指令（"处理收件箱的 task_assignment / fix_request / review_request"）才动。
2. tester 对 round 2 review_request（20:18 落盘）的验收延迟 **47 分钟**（21:05 才产出
   verdict_pass，且该产出是注入指令后的结果）——若自动唤醒存在，10s 轮询早该处理。
3. 三个窗口进程全程存活（Get-CimInstance 实测：arch 19904 / dev 22624 / tester 43340，
   均在临时空项目目录），排除"窗口死了"。
4. 剧本（dev 第一版故意写 not yet 触发 FAIL）依赖人在 arch 窗口注入——arch 不会自发
   在 task_assignment body 里写"请故意犯错"。

## 根因 M6-010 [serious]：唤醒链路缺失（实现里不存在）

- `watchInbox`（01-channel 的 fs.watch + 10s 轮询兜底）在 `src/adapter/` **零调用**：
  `grep -rn "watchInbox" src/` 仅命中注释（channel 定义 + status.ts 注释）。
- `git log -S "watchInbox(ctx.cwd" -- src/` 为空——**从未接线过**，不是回归删除。
- `src/adapter/status.ts:11` 注释：「wire 的 session_start / **watchInbox** 共用同一份」
  ——设计上 wire 应启动 watchInbox，实现没做（D-02 的精确形状：写了但没接线，且无机制抓）。
- 后果：消息落盘 → 无任何通知 → pi agent 只在收到 user 消息时跑 → 窗口永远等不到消息，
  全靠人踢。**M6.6 自动成环在机制上不可能成立。**

## 为什么测试没抓到

E1 / mock-pi 全部**直调驱动**（emit 事件、直调 execute），唤醒是"消息落盘 → 窗口收到
通知"这条真实路径，mock 完全绕过。plan.md 风险节预告的形状（「mock-pi 验的是接线正确，
不验 pi 真实行为：事件时序、sendUserMessage 语义、系统提示注入链」）被真实验证出来——
这正是 M6.6 [human] 断言存在的理由。

## 连带问题 M6-011 [medium]：FAIL 演练依赖人注入剧本

M6.md 步骤 5 要求 dev 第一版"故意不含 ok"，但 arch→dev 的 task_assignment 是自动流转，
arch 不会自发写"请故意犯错"。实测 dev 两次都忠于 plan 断言写了含 ok 的内容。
FAIL 演练要么靠真实缺陷触发（不预演），要么接受"fix_request 通道已由 R5 在本仓库
真窗口验过"，M6.6 只验主链路自动成环。

## 建议修复方向（待 arch/人裁决）

1. wire() 接线：session_start 时启动 `watchInbox(ctx.cwd, role, (msg) => pi.sendUserMessage(...),
   { onWake: 打印 poll/event/catchup 触发源 })`——onWake 日志是 C1 人工断言的观测点。
2. 句柄跨事件持有：`Map<root, Stop>`（keyed by root 满足 D-07 的 root 隔离判据），
   或挂 pi 的 session 生命周期（待查 SessionStartEvent ctx 挂载点）。
3. 补测试：fakePi 触发 session_start → 投真实消息进收件箱 → 断言 sendUserMessage 被调 +
   触发源日志；E1 增补"消息到达 → 窗口被唤醒"（D-25 真实落盘路径）。
4. 修完重跑 M6.6，**全程不注入**观察——判据 1/3 的本意。
5. M6-011：M6.md 步骤 5 的 FAIL 演练改为真实缺陷或移除（见上）。
