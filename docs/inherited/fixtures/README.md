> 来源：`前身仓库 work-flow-paper`（留档项目，唯一真实跑过四个里程碑的接入项目）。
> **这些文件不修改、不美化、不补节。** 它们的价值恰恰在于「当年出了什么错」。
>
> 复制过来的理由：留档仓库随时可能被清理，而这批文件是唯一能证明
> 「新判据抓得住老失效」的输入。自造 fixture 做不到这一点——它只能证明代码符合我的预期。

| 文件 | 当年的问题 | 谁用它 | 期望结果 |
|---|---|---|---|
| `paper-plan.md` | 四个里程碑用行内 `验收：…`，**无 `### 验收` 小节**（实测 0 处）。当年 `planQualityGate` 对 M1–M4 全部返回 `ok:false`，而四个里程碑全部人工验收通过——格式分裂了两个月无人发现 | 04-plan `L9` | 解析失败，错误含行号并指出缺断言节 |

| `paper-dev-output-M4.md` | 无问题——三小节齐全（实测 3/3） | 05-gates `T2` 反向 | **放行**（防误伤） |

## 为什么要留一份「正确的」

`paper-dev-output-M4.md` 是对照组。老仓库那组数据的说服力来自对比：

- tester 报告 **0/4** 写了要求的节
- dev 产出 **4/4** 写齐了要求的节
- 唯一差别：dev 的拦截提示文案里明文列了小节名，tester 的没列

只测「坏输入被拦」会漏掉误伤。T2 拿这份好输入验证 gate 不会把合格产出也拦下来。

## 判据变了，输入仍然有效

新的 G-artifact 不再要求固定小节，改为「每条断言一行结论」（D-22）。所以：

- 四份 test-report 现在**因为缺断言编号覆盖**而 block，不再因为缺「文档一致性」节
- `paper-dev-output-M4.md` 严格说也不满足新判据（它对着旧格式写的，没有断言编号）

**T2/T10 使用它们时要显式构造对应的 `Milestone`**（从 `paper-plan.md` 解析不出来，得手写一个最小 Milestone 传进去）。这一点在写测试时不要绕：绕过去就等于自造 fixture，失去了「真实输入」的意义。
