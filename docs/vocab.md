> 术语歧义已实测造成对话往返成本（见「已判定的歧义」节）——本文件是唯一权威，

> ## 两套语言（2026-08-24 定：语料化）
>
> 实测（模型语料 = 规约 + 工具面 + 简报 + gate 文案，不含注释）：表内 20 词里
> 17 个在模型语料零出现，而模型语料高频的「收尾/验收/铁律」表里没有——
> **词汇表之前描述的是开发者读的文档的语言，不是模型读的 prompt 的语言。**
> 所以按「谁读」分两类登记：**模型** = 注入规约/工具面/简报/gate 文案里实际出现的词，
> 模型必须用一致的叫法；**文档** = 开发者讨论与文档专用，模型不需要。
>
> 检查（`npm run check:vocab`）：
> - **存在性**：标「模型」的词必须在模型语料中实际出现（零出现 = 声称模型用而模型不用，
>   与 D-02 同形）。标「文档」的词允许零出现。
> - **唯一性**：语料中高频出现的**表外**概念词会被报告（候选：登记进表，或改语料用表内词）。
> - 粒度边界：不查大小写（`type Frontier` 是语言惯例）；不含注释（注释会引用纪律原文）。

## 术语

| 词 | 定义 | 类别 |
|---|---|---|
| **里程碑（milestone）** | 规划书里一个可验收的单元，带断言表。id 如 `M1` | 模型 |
| **断言（assertion）** | 里程碑内的可判定条目，`[auto]` / `[human]` 二分（D-20） | 模型 |
| **判据** | 某条纪律/门「怎么算违反」的表述。纪律表每行有判据列 | 模型 |
| **未决（frontier）** | 规划书的「未决表」。同一概念，代码里叫 `frontier.ts`。_避免_：写成「待办」——未决是能精确陈述但答不了的问题（D-10），待办是执行项 | 模型 |
| **判定** | 验收动作（PASS / FAIL）。判定权在 tester / 人，不在生产者（D-01） | 模型 |
| **放行** | 人的确认动作——arch 把「M 可以过」整理成凭证三段给人确认后，代发 milestone_passed。与「判定」区分：判定是 PASS/FAIL，放行是人点头（arch.md / human.md 意图表高频） | 模型 |
| **凭证** | 人工验证落盘记录（`docs/verification/*.md`），含判定 + 依据 + 签字 | 模型 |
| **收缩** | **只指 D-06 的文档收缩**（模块文档拆进代码与测试）。_避免_：指项目瘦身（说「瘦身」）或里程碑收尾（说「收尾」） | 模型 |
| **收尾** | 里程碑结束动作：验收、标 ✅、重生进度表、凭证落盘（arch.md 高频使用；与「收缩」区分） | 模型 |
| **验收** | 判定一个里程碑的断言全过（tester 跑 [auto] + 人答 [human]） | 模型 |
| **铁律** | 角色规约里「不得违反」档的条目（arch/dev/tester.md 的「铁律」节） | 模型 |
| **落点** | 纪律「在哪被强制」。落点为「规约」= 只写在文本里，接受被跳过（D-02） | 文档 |
| **机制** | 有自动化强制力的落点（测试 / gate / 脚本），相对「规约」而言 | 文档 |
| **gate（拦截链）** | `tool_call` 上跑的纯函数判定链，返回 `{ok, reason}`。一道不过就 block | 文档 |
| **block** | 拦截动作——`tool_call` 返回 block，LLM 收到 reason，投递不生效 | 文档 |
| **签字** | 人对断言/判定的确认动作（D-24 逐条签字；D-15 断言节只有人能改） | 文档 |
| **唤醒（watchInbox / onWake）** | 消息落盘 → 窗口收到通知的链路。onWake 是触发源日志 | 文档 |
| **单槽位** | 收件箱一文件一消息，严格串行（`inbox.ts`）；2026-08-24 起是锁（共识 #4） | 文档 |
| **水位（watermark）** | `.processed-{role}` 的 mtime 标记，防重复处理（C3） | 文档 |
| **真空绿** | 断言永远满足、永远红不了——被验收者钻空子的形状。来源：L6 `some(!passed)` 全验收后不可满足（d10d1eb） | 文档 |
| **红场景** | 断言在什么具体条件下会红（文件名/命令/条件）。写不出红场景的断言不合格（可失败性检查） | 文档 |
| **src:ai / src:human** | 断言署名标记。AI 起草 = `src:ai`；人确认改 `src:human`，git diff 即签字物证（D-21 机制化） | 文档 |
| **横切 / 垂直切片** | 横向切片 = 一层一层做（M1–M6 的形态）；垂直切片 = 穿所有层的最薄完整路径（walking skeleton） | 文档 |
| **塌缩** | D-16「规划书要能塌缩」——最小合法形态（一里程碑 + 一断言 + 未决表「无」）。与「收缩」字面接近、含义无关 | 文档 |

## 关系

- 一条纪律有一个**落点**；落点是「规约」= 承认会被跳过
- 一个里程碑有一组**断言**；断言是验收的最小单元
- **未决** = frontier 分组；**落点** = 机制或规约——两个词不混
- **判定** ≠ **签字**：判定是 PASS/FAIL，签字是人确认动作
- **收缩** ≠ **塌缩** ≠ **收尾**：文档收缩 / 规划书最小形态 / 里程碑结束

## 已判定的歧义

- **「收缩」三义**：D-06 文档收缩 / 项目瘦身 / 里程碑收尾，一次对话被迫往返澄清。
  已判定：只指 D-06 文档收缩。（来源：2026-08-24 对话事故）
- **「落点 vs 落盘」**：纪律落在哪 vs 写文件——一字之差，两义。
  已判定：落点 = 纪律强制位置；落盘 = 凭证写入文件。（来源：日常混用）
- **「frontier vs 未决」**：同一概念中英双写（`frontier.ts` / 未决表）。
  已判定：同一概念，按上下文用；代码侧固定 `frontier`。（来源：项目自述）
- **「gate / 拦截链 / 判定」**：同一层三个叫法。
  已判定：`gate` = 单道纯函数；拦截链 = gate 串；判定 = PASS/FAIL 动作。（来源：README 与代码混用）
- **「待办 vs 未决」**：执行项 vs 可精确陈述但答不了的问题。
  已判定：未决进未决表，待办进收件箱。（来源：D-10 澄清规约）
