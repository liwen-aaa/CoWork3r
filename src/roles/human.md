# 人的规约（2026-08-24 定，共识 ②）

> 这不是角色规约，是**给你的操作说明**——不进任何 system prompt，按需读。
> 你的全部操作就三件：**看、说、确认**。其余都是三个窗口的事。

## 你的三件事

**看**：窗口启动简报与 `/status` 给你四行「里程碑 / 轮次 / 待你判定 / 未决」。等你判定的事逐条记在 `wf/human-pending.md`（未勾选的 `- [ ]` 就是还没回答的）——你不需要记任何状态。

**说**：只对 arch 窗口说人话，arch 翻译成确定格式。

| 你说 | 发生什么 |
|---|---|
| 「M1 可以过」 | arch 整理凭证 → **给你看 → 你确认** → 放行 |
| 回答它列出的问题 | 答案记进凭证，随放行落盘 |
| 「不行，因为…」 | arch 整理给 tester，它决定发不发回 dev |
| 「方向不对 / 卡住了」 | arch 读状态给你解释，或升级给 tester |
| 对 dev/tester 窗口直接说 | 那是打断——窗口会自动留痕，但你的话直接生效（不进协议） |

**确认**：只有放行时需要。arch 会把凭证（你的原话 + 它的整理）贴给你看，你说「确认」或「不对」。**放行是单向门，发错了整个里程碑白做——所以只有它需要你点一次头。**

一次确认只管一次放行：你说「不行」重走一轮后，机器会把上次的许可作废，arch 必须等 tester 报新的验收通过才能再来问你。

## 你判什么 / 不判什么

- 判：`[human]` 断言（只有你能答的那些）；放行与否。
- 不判：`[auto]` 断言（机械，tester 跑）；实现方式（那是 dev 的事）。

## 设计决策：执刀关系按领域流动（2026-08-24）

决策拆两层，流动的只有一层：

```
目的层(为什么做、边界、验收标准、取舍)  → 从不流动，始终是你
领域层(怎么实现、技术选型、领域最佳实践) → 按熟悉度流动：谁懂谁执刀
```

- 你熟悉的领域：你执刀，agent 当陪练（评审、提问、站在同一水位审核）。
- 陌生领域：agent 执刀（它训练数据里有领域知识），你持有目的 + 用断言评审——
  你审的不是技术细节（审不动也不该审），是「产出是否满足可判定断言」：
  `[auto]` 机器跑、`[human]` 你判。**可判定断言是不懂领域的人评审懂领域的 agent 的唯一工具。**
- 副手（评审你的那个 agent）不豁免 D-01：它的产出同样要被机制/人审，
  你评审它，不是信它。

**锚：无论谁执刀，验收标准（目的层）永远在你手里。** 这就是 D-15
（断言只有人能改）真正的含义——不是因为你最懂技术，是因为验收标准是目的层的。

## 你持有判据（D-51，2026-08-24）

评分函数是判据的投影，投影漏维度；持有权交给产出者，投影上没有的东西就消失
（Goodhart）。所以 gate 判据的本体变更**要你批**，agent 必须按 D-15 同款形状
升级给你（写清怎么改+为什么+三选项）再等批：

```
要你批的（判据本体）:  agent 自主的（实现层）:
  匹配规则               reason 文案措辞（判据不变、表达变）
  阈值（D-41/A6/maxRounds） 代码重构
  必填字段（requires）     新 gate 接线
  check 脚本判据（ALLOWED）
```

日常零打扰：判据是稳定层，变更罕见。被频繁问到 = 判据质量信号（太松/太紧），
处理判据本身，不是多走流程。

## 你的边界

- 你可以在任何窗口直接打断（通道 B），但打断会被留痕——凭证要能看见「这轮有外部输入」。
- 你不修改协议、不写文件、不手工投递——那是窗口的事。你说人话，arch 翻译。
- 台账里处理完的条目由你划掉或删行；AI 不动它的历史（D-34）。
- 你想改断言：arch 会按 D-15 把改法写进风险节并升级给你，你签字，它不替你改。
