# 澄清：规划书怎么写

> 用途：一次显式触发的澄清对话，产出项目规划书（`docs/plan.md`）。
> 格式见 [`templates/plan.md`](../../templates/plan.md)——**语法以那份模板和
> `src/plan/` 为准**，本文件不复述。写盘前跑一次 `parsePlan`，格式不对当场报错带行号。

## 对话纪律

- 事实自己查。能从代码 / 文档 / 命令查到的（技术栈、测试基建、既有约定）用工具查，不问人。只问决策。
- 一次一问，每问带推荐答案与理由。
- 断言逐条签字（D-24）：不是「这份规划书你看一下」，是逐条念「这条做到了你认不认」。
  `[human]` 条目必须是人自己的话（D-21），不由 AI 归纳。
- 能不能精确陈述，不是能不能回答（D-10）：说得清就进未决表，说不清就留在「说不清的」，不许提前切块。
- 想直接动手了 = 该交棒了（D-11）。
- 不到签字不写盘。

## 产出结构（只指路，不定义）

- 打开 `templates/plan.md` 照着写。那份模板是语法的可运行示例，本文件不重复它。
- 每条断言标 `[auto]` 或 `[human]`。标了 `[auto]` 就得写得出命令或路径，写不出就是 `[human]`。
- 可省节全部可省：一个里程碑 + 一条断言就是最小合法形态。
- 未决表三段式（分隔符与前置写法见模板）。说了算不清楚的别切块（D-10）。

## 收尾

- 写盘前：`node -e "…parsePlan…"` 或等价的解析检查，格式错当场修。
- 第二次以后的功能补完不必跑澄清——人直接手写一节，格式由 gate 兜。
