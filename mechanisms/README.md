# 机制包（mechanisms）

> 可移植的单元**不是纪律的文字，是「判据原文 + 会红的机制」这一对**。
> 判据单独走 = 落点退回「规约」= 接受它会被跳过（D-02）。机制随代码走才带得动执行力（T12）。

运行器：[`../scripts/mech.mjs`](../scripts/mech.mjs)。装机与使用流程见 [`../README.md`](../README.md#把纪律带进新项目机制包)。

## 一个包四件东西

```
mechanisms/<id>/
  pack.json      元数据：一句话判据 / 来源事故 / 适用范围 / 缺省参数
  criterion.md   判据原文。**被拦时随 reason 一起打印**——这是它按需到达的唯一形态
  check.mjs      export function check({ root, options }) → { ok, reason? }
  fixture/<case>/  会红的真实输入（准入闸拿它真跑，红不了就拒装）
    fixture.json   { expectRed, why, git?, options? }
    files/         铺进临时项目根
```

`check` 纯读盘 + git，不写任何文件，不依赖被检项目的语言与构建工具。

## 准入闸：为什么装机要先证明它会红

`mech install` 先跑 `selftest`（fixture 必须红）再在本项目跑一次（本项目应该绿）。两头都卡住，包才不可能是这两种坏形态：

- **恒绿**：有实现、有文档、有测试，而任何输入都过不了它 —— 比没有防线更危险，因为你以为有（D-49 那一档）。
- **恒红**：装上就红且修不动，于是被 skip 掉，接着整条 pretest 都没人看。

这就是 T14 的红场景标准搬到装机时刻执行：**写不出会红的真实输入 = 它是投影不是判据。** 写不出的经验本来就该留在散文里被跳过，装上去只是让人以为有防线。

## 加一个包的准入

一条经验有资格成包，要同时满足：

1. 有**被观察到的失败模式**（pack.json 的 `origin` 写清那次事故，D-40 第①问）。
2. 写得出 fixture（否则见上）。
3. 机制与被检项目的语言无关，或在 pack.json 的 `applies` 写清适用范围。
4. 判据是判据、不是某个仓库的形状 —— `src/ 里 pi 只能 import type` 这类留在原仓库，不进包。

**新包的唯一合法来源是下游项目的真实事故**：哪个项目撞出一个能写红场景的新形状，它才有资格升级成包发回来。按预判增长的包数就是元机制膨胀本身（E9：src 1997 行 vs 元机制 7650 行）。

## 判据持有权（D-51 的反向坑）

判据从上游包来，意味着**持有权离开了人**：升级包会静默换掉判据，而人从没被问过 —— A9f 那次「凭证可捏造」的镜像形状。所以：

- 包按 ref 钉住，不 `pi update` 一把过；
- 升级时把 `criterion.md` 的 diff 摆给人批（同 D-15/D-51 的形状：怎么改 + 为什么 + 三选项）；
- 项目侧参数（`mech.json` 的 `options`）人可以改，判据本体不由项目改 —— 要改就改包，走上游。

## 现有包

| id | 判据一句话 | 适用 |
|---|---|---|
| `append-only-ledger` | 台账条目只增不改，编号严格递增（乱序会掩盖删除） | 任何语言（纯 text + git） |
| `claimed-landing` | 标了「已物化」的落点必须真存在 | 任何语言（纯 text + fs） |
| `wired-check` | 台账声称的检查命令必须存在且已进每轮钩子 | Node（读 package.json scripts） |

前两个语言无关，是新项目 day 0 的缺省装机集。`wired-check` 绑 npm 生态，判据通用而机制要按生态换适配器 —— 换生态时只重写 `check.mjs`，`criterion.md` 不动。
